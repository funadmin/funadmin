# 后台公共按钮权限判断与覆盖计划

> **For agentic workers:** 使用统一接口分模块修复；共享权限工具由主代理实现，独立页面模块按 dispatching-parallel-agents 并行处理。

**Goal:** 后台业务操作统一使用公共权限判断，补齐按钮和操作入口的权限控制；字段权限留待后续。

**Architecture:** 在 `web/src/shared/utils/permission.ts` 提供公共 `hasPermission(required, mode)` 和纯函数 `checkPermission(granted, required, mode)`，`v-perm` 复用该判断。现有权限码、超管通配符、后端 RBAC、数据范围与插件激活规则继续使用；各页面依据对应后端操作配置按钮和提交入口，不新建平行权限体系。

**Tech Stack:** Vue 3、TypeScript、Pinia、Vitest、Webman RBAC。

## Global Constraints

- 用户明确只做菜单/按钮操作权限，字段查看和编辑授权不在本次范围内。
- 公共接口：`hasPermission(required: string | readonly string[] | null | undefined, mode: 'any' | 'all' = 'any'): boolean`。无声明的可选权限允许；有效权限默认精确匹配，`*` 和 `*:*:*` 是现有超级权限。
- 复用现有 `v-perm` / `v-perm:all` 写法；指令应随权限变动更新，并能在重新授权后恢复按钮。
- 保护后台业务操作。取消、返回、关闭、折叠等纯界面操作不附加无关权限；登录、安装、本人资料依据其原有认证流程。
- 前端控制不替代后端接口 RBAC；不把浏览页面权限视为新增、修改、删除权限。
- 保留当前工作区已有未提交改动，不提交、不推送此次变更，除非用户另外要求。

## Review Focus

1. 普通角色仅有查看权限时不得发起写操作。
2. 权限运行中被撤销后按钮和提交入口应采用最新权限。
3. 任一/全部权限、缺省可选权限与超级权限含义一致。
4. 弹窗确认、上传读取等异步步骤后再次核对权限再提交。
5. 插件与动态表单继续使用声明的动作权限及原有范围限制，不能退回页面级笼统授权。
