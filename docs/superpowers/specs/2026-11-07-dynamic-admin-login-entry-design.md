# 动态后台登录入口设计

用户需要在安装时设置后台登录入口，并在遭遇暴力破解时由人工修改入口。方案保持 `/admin` API 命名空间，动态部分为 `/admin/{entry}/auth/*`；默认入口 `admin` 继续兼容现有页面 `/#/admin/login`，自定义入口页面为 `/#/admin/{entry}/login`。

入口使用小写字母开头、字母数字和短横线组成，长度 4～32，禁止 `login`、`auth`、`install`、`api`、`system` 等保留词。入口保存为系统配置 `system.admin_login_path`，安装时初始写入；已安装系统在系统配置页由超级管理员修改。旧入口 API 返回 404，旧前端页即使被缓存也无法完成认证。

认证控制器注册动态路由 `/admin/{entry}/auth/{csrf,login,me,menus,logout}`，每个动作校验路径参数等于当前配置。前端根据路由参数和本地保存入口请求对应 API；安装响应返回动态登录 URL。默认入口不改变现有 `/admin/login` 页面体验。

安全边界：入口修改需要现有超级管理员会话与 CSRF；修改成功后当前管理员会话不强制退出，但旧入口立即失效。入口本身是降低扫描噪音的防护，不代替限流、强密码和审计；现有认证限流继续有效。
