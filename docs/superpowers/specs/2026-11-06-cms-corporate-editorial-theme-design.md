# CMS 企业官网与资讯统一主题

2026-11-06。用户在前台设计提案后明确“企业网址和文章资讯都要”。按已提出的现代门户、暖白/墨绿、响应式、SSR 方案实施统一主题。技术和具体版式由实现者确定。

## 目标与选择

同一站点同时承担企业展示与文章资讯，不建立两个站点或两套导航。曾考虑纯资讯杂志（缺少产品/案例表达）、企业落地页（弱化阅读）、统一企业+资讯主题（采用，与用户确认用途吻合）。

交付首页、栏目列表、文章详情、产品详情、案例详情、企业单页、搜索页；下载模型继续可用。所有页面共用导航、语言选择、面包屑、页脚、内容卡片和响应式尺度。

## 视觉设计

暖白 #f7f7f2、深绿 #183e35、酸橙 #d8eb8b、灰绿文字；清晰的大号中文标题与小号英文眉题，细分隔线、少量圆角、大留白。首页品牌展示采用左右不对称布局与本地 SVG 建筑/空间插画，随后企业内容入口、精选产品、案例、最新资讯。标题和简介可由站点/语言 settings 的 presentation 配置覆盖；不编造客户、业绩和业务承诺。

企业与资讯使用真实已发布数据。栏目卡片、封面、摘要、文章信息、模型字段及 SEO 继续来自现有 CMS。缺少封面显示本地抽象插画；无数据用访客可理解的简洁提示，不自动向真实站点注入样例内容。用户已配置菜单继续采用原导航；无菜单时使用本地化首页/内容锚点与搜索入口。

## 行为与边界

- PHP 模板直接输出完整 HTML，普通 Vue/Element Plus 脚本仅渐进增强，不进行前台 npm 打包，不新增客户端路由。
- 使用现有字段/模板机制。默认 detail 按真实 model_code 选布局：article 文章、product 产品、case 案例、page 企业单页、download 资料下载；显式自定义模板仍优先。
- 搜索使用独立 search 模板；首页第二页仍为全内容分页，避免企业首页模块误重复分页/筛选。
- 站点/语言隔离、草稿不可见、真实状态码、canonical/hreflang/结构化数据保持。静态界面文案至少中文与英文，其他语言可覆盖 presentation 文案，默认英文回退。
- 安全封面解析只接受有效、未删除、启用的附件和已有 HtmlSanitizer 允许的 URL，不把危险链接写入模板。不创建动态模板代码执行。
- 移动导航使用原生 details，无 JS 可展开；搜索表单无 JS 可提交；尊重 reduced-motion；跳过导航链接与键盘焦点可见。
- 保留所有真实内容/角色/域名，发布使用正常资源和原生 App 发布器；前台资源/模板升级不依赖旧入口兼容。

## 实现分解

展示上下文单独服务负责标签、企业/资讯内容列表、封面和字段视图，不修改 Schema。模板只消费展示数据。SSR 回归覆盖真实 URL、缺图、空站、多语言、模型布局与搜索分页。浏览器验证桌面/手机和关闭 JS。演示数据仅进入独立测试数据库。

## 用户补充：每站基础配置与自定义配置项

用户在开发中明确要求“每个站点是不是少了一些基本配置，配置需要可以自定义添加”。纳入本轮：站点管理页增加配置面板，预置品牌/Logo/favicon/首页文案/联系方式/版权备案，并可按站点新增分组及配置键、名称、类型、可翻译标记、默认值。支持 text、textarea、number、boolean、url、email、image URL、color、select。

数据使用现有 cms_site.settings.configuration（fields + values）和 cms_site_locale.settings.configuration.values（仅可翻译值覆盖），无需新 SQL。模板通过 config 对象和 cms:config 标签访问已校验的公开值；页面展示配置不用于保存密码/API密钥。locale 只覆盖值，定义属于站点；false/0/空字符串有效，只有显式移除覆盖才继承。切站互不影响，先读本站值，再叠加所选语言覆盖。

查看配置需 site:detail；保存字段定义/站点值需 site:edit；保存语言值需 site:locale，仍与宿主 site:list/save 资格取交集。通用 sites/save 与 locales/save 的 settings 也执行同样校验，不能绕过独立接口。前台主题接入 Logo/favicon、品牌短名、hero标题/副标题/描述、联系方式、版权备案；其余自定义字段可在任意模板读取。
