> 目录部分已由 `2026-11-05-plugin-layout-design.md` 取代。当前规范见 `docs/plugins.md`，不再保留简写目录及旧发布记录兼容。

用户已确认按插件适配检查结果实施。保留 Manifest v2、生命周期、签名包、资源归属、恢复日志和显式数据清理。

采用现有 Webman 模块结构：后台源码发布到 `app/admin/plugin/business/{code}/{layer}`，命名空间与目录一致；后台 API 为 `/admin/plugin/{code}/…`，独立应用为 `/{code}/…`。插件源包仍使用 `app/admin/{layer}`。声明权限通过插件中间件校验，不再让生成插件走核心控制器权限推导。启停守卫使用 Webman `process()` 并接入全局配置。

前端源码发布到同级 `web/src/admin/plugins/{code}`；可通过配置指定前端根目录。Webman 启用插件模块加载，页面路径使用现有 `/admin` 路由约定。前端仍需构建收录新增源码，不引入远程脚本加载。

同步脚手架、CRUD、Manifest 校验、执行代理和示例代码。验证真实 HTTP 中间件链、普通用户权限、禁用/异常激活清单、源码发布恢复、生成代码和路由挂载。

## Approaches

- 局部修补旧目录：改动小，但继续维护两套命名空间和路由规则。
- 完整适配现有模块结构（采用）：保留成熟的生命周期机制，统一生成、发布与运行边界。
- 重建插件框架：涉及包契约和数据迁移，超出本次需求。

约束：不覆盖用户已有修改，不执行生产数据库迁移，不安装新依赖。已有插件的旧目录资源必须有明确恢复/迁移处理，不能静默丢弃归属或覆盖人工修改。
