# CMS 子菜单与站点菜单/按钮权限

日期：2026-11-05。状态：用户已确认，进入开发。扩展已安装 CMS，新要求来自用户：独立子菜单、A 管站点1/B 管站点2，以及每站点的每个菜单和按钮权限。用户明确第一版粒度为菜单和按钮。

## 目标与范围

- CMS 成为父目录，各管理功能使用独立子菜单、页面路由和权限。
- 同一管理员可负责多个站点，在各站点拥有不同菜单/按钮权限。
- 站点内使用可复用角色，支持自定义角色和多角色；后台提供树形菜单/按钮勾选与成员角色分配。
- 后端检查每次请求的站点、操作和关联对象，隐藏按钮只是界面表现。
- 保留现有内容、多语言、模板、自定义 URL、修订和附件机制。
- 本轮不增加按栏目、内容语言、字段或“仅本人内容”的数据范围限制；全局模型定义仍为平台能力。

## Approaches

1. 给每人每站直接勾所有权限：容易起步，但人员多时重复配置，职责调整难统一。
2. 站点角色和成员绑定（采用）：每个站点维护角色，将功能操作权限交给角色，成员可分配多个角色。
3. 将全部站点权限复制到系统角色：角色数量随站点增长，并且难区分平台权限和站点范围。

采用第二种，保留宿主系统角色作为能力上限，不自动给任何真实账号扩大系统权限。站点范围与功能操作是两个必须同时满足的条件。

## 菜单与页面

```text
CMS 内容管理
  站点管理       /admin/plugin/cms/sites
  栏目管理       /admin/plugin/cms/categories
  内容管理       /admin/plugin/cms/content
  导航管理       /admin/plugin/cms/menus
  模板标签       /admin/plugin/cms/tags
  内容模型       /admin/plugin/cms/models
  站点权限       /admin/plugin/cms/access
```

页面 URL 为前端 hash 路由。管理 API 仍在 `/admin/plugin/cms/...` 下，两者职责不同。站点管理页保留域名、语言、主题等设置，站点权限页包含成员和角色两个部分。保留旧 `/admin/plugin/cms/manage` 书签，重定向到用户第一个可用页面，不保留旧 Tab 总览页。

共享站点/语言上下文，切换页面保留当前选择。各页面站点选择器只列出该账号对当前菜单有权访问的站点；当前站点不可访问时选择第一项可访问站点。无可访问站点显示明确空状态；手工修改 URL 或 API 的站点 ID 仍拒绝。

单站单语言隐藏冗余选择器，保留紧凑的站点名称与语言提示，继续使用宿主 PageWrapper、DataTableShell 和现有抽屉/对话框。

## 权限语义

普通账号的有效权限：

```text
宿主系统角色允许的 CMS 操作
  ∩
当前站点成员绑定的启用角色权限并集
```

不支持显式 deny，未授予即拒绝。多站点之间不合并操作授权。平台超级管理员保持宿主原有规则，可管理所有站点。

例：

| 账号 | 站点 | 角色 | 有效操作 |
|---|---|---|---|
| A | 站点1 | 编辑 | 查看栏目和内容、保存草稿、预览；不能发布 |
| A | 站点2 | 只读 | 查看内容；不能保存或发布 |
| B | 站点2 | 发布 | 查看、保存草稿、预览、发布、下架 |
| B | 站点1 | 无 | 站点不出现在选择器；请求拒绝 |

以上始终受宿主系统角色上限约束。授权界面展示缺失的系统资格，避免用户勾了站点权限却不知道为何不能生效；站点角色不会替代或绕过系统角色。

左侧显示账号在任一可访问站点具备的菜单。进入菜单后按本站有效权限显示按钮。菜单发现和页面路由过滤使用有效权限的跨站并集，但 API 永远使用当前单一站点的权限，不将该并集用于请求授权。

宿主增加可选的插件权限范围过滤扩展，过滤器只能缩小原有插件权限，不得产生新的系统权限。CMS 用它对自身菜单/页面目录进行跨站有效权限过滤。未安装/停用/未迁移的 CMS 权限按缺省拒绝处理，不影响核心或其他插件。具体扩展注册方式在实施计划中与现有 Hook/Manifest 契约统一，不在核心硬编码 CMS 类。

`cms:site:list` 保留为基础站点发现资格，不再代表查看完整站点设置。新增站点详情权限区分“可选择站点”和“可管理设置”；所有成员可获取已授权站点的最小上下文（ID、显示名称、启用语言和有效操作），不可因此读取完整域名设置或成员列表。

## 菜单及按钮目录

以正式 permission code 为唯一标识，名称使用中文，父节点仅负责分组。按钮权限与真实 API 行为一一对应，不只在前端配置。

- 站点：查看设置、修改基本设置、域名管理、语言管理。新建/删除站点仍为平台操作。
- 栏目：查看、新建、编辑、启停。当前已有的保存接口按是否存在 ID 分别校验新建与编辑，不能靠传入 ID 绕过。
- 内容：查看、新建、编辑草稿、预览、发布（含发布历史修订）、下架。未实现的删除操作不展示空按钮或授予虚假权限。
- 导航：查看、新建、编辑、启停。
- 模板标签：查看、新建、编辑草稿、预览、发布；可用处理器目录遵守标签查看/编辑权限。
- 内容模型：查看、本站启停、设置本站默认模板。创建/修改全局模型定义仍仅平台管理员，不能通过站点角色获得。
- 站点权限：查看成员/角色、管理成员、管理角色/角色权限。

保存类 API 根据资源类型及创建/更新意图区分操作权限；启停或设置变更也检查对应权限，不能使用“编辑”请求顺带开启未授权能力。所有菜单/按钮进入统一站点权限目录，由宿主已注册且启用的 CMS 权限引用，拒绝跨插件 code、通配符及未知 code。

只读/编辑/发布/站点管理员为新站点可用的初始角色，可以按站点复制或调整。只读角色不含任何写操作。编辑角色不含发布、域名/语言管理或授权。发布角色不含站点授权。站点管理员角色包含本站范围操作，不含创建其他站点或编辑全局模型定义。

## 数据结构

新迁移 `002_site_roles.sql`，不修改已经执行的 `001_cms.sql`；插件版本升级为 1.1.0。新增：

- `cms_site_role`：id、site_id、code、name、status、created_at、updated_at、deleted_at，站点内 code 唯一。
- `cms_site_role_permission`：site_id、role_id、permission_code，复合唯一；保存时验证 role 与 permission 的归属。
- `cms_site_role_member`：site_id、role_id、admin_id，复合唯一。
- `cms_site_auth_audit`：site_id、actor_admin_id、target_type、target_id、operation、before_state、after_state、created_at，记录成员及角色授权变化，不记录登录凭据。

沿用 `cms_site_admin` 记录站点成员身份；角色成员变更与身份记录在同事务维护。成员存在但没有有效角色时没有业务操作权限，不隐式放行。普通角色停用、删除后即不再参与有效权限。

所有授权写操作锁定站点，校验实际操作人权限后事务写入并记录审计。角色关联 ID、成员 ID、对象 ID 必须属于目标站点及宿主可管理用户范围。

## 授权边界

- 平台管理员可管理全部站点授权。
- 普通站点授权管理员只能管理自己有权限的站点，以及宿主允许其管理的账号；可授权权限不能超过自己的本站有效权限。
- 不能通过创建/修改共享角色、分配已有高权角色、自我绑定、角色 ID 跨站替换等方式提权。
- 不可向其他站点授予权限，不改宿主系统角色，不把本人缺少的权限交给其他人。
- 读取设置、列成员、列角色也有独立权限，避免仅有内容查看权就能读取后台管理数据。
- 撤销成员/角色或停用角色在下一次请求立即生效，不依赖 Worker 重载。页面刷新/权限上下文刷新后同步菜单和按钮。
- 继续保留浏览器登录、宿主功能权限、CSRF、插件启停与关联对象范围检查。

## 插件层级菜单契约

- `adminWeb.menu` 增加递归 `menulist`，目录节点可以不声明页面组件/按钮权限；叶子必须绑定已声明权限与可加载路由。
- 递归校验命名空间、路径、权限引用、深度和数量；不可借嵌套项绕过顶层限制。
- 安装/升级以插件来源登记父子菜单，顺序稳定、可重复执行。
- 未再声明的子菜单也递归停用，保留人工修改保护和资源归属。
- 空目录不展示；用户只要有可用子项就能看到父目录，不要求额外站点设置权限。
- CMS 源包显式声明七个子菜单及独立组件；框架补齐通用能力，不在 CMS 页面硬写侧栏 DOM。

## 升级与当前环境

- 既有站点和内容保留。已有站点成员迁移为兼容角色，保持原先在宿主权限上限下的有效站点能力；不自动赋予此前仅超级管理员可用的授权或平台能力。
- 新增权限需要按宿主正式资源注册流程登记，不能为普通账号静默扩大系统权限。
- 权限表未迁移时不假装有权限，返回明确“请完成 CMS 升级”的状态；超级管理员可以通过插件中心正常升级。
- 不自动给真实 A/B 账号分配权限；用隔离测试账号和两站点验证。
- 先交付、验证插件升级与菜单契约。当前开发环境使用正式生命周期执行迁移/发布时，保留恢复日志并检查已有人工修改；不重装、不删除现有站点。

## 验收

1. 左侧出现父目录和七个按权限过滤的子菜单；旧 manage 地址可用，页面不再依赖 Tab 切换。
2. A 在站点1编辑、站点2只读；B 在站点2发布，不能访问站点1。站点列表、直接 API、手工 ID、路由均覆盖。
3. 菜单、查看、新建、编辑、预览、发布、下架及设置/授权按钮分别测试；一个允许另一个拒绝。
4. 编辑账号不能通过修改 ID 新建、通过新建参数编辑、通过保存顺带启停、通过历史版本接口绕过发布权限。
5. 仅内容菜单授权也能获取最小上下文，不泄露设置/成员信息，不要求站点设置菜单权限。
6. 对多个角色求并集，对宿主上限求交集；同一 code 在别的站点不生效；撤权下一请求拒绝。
7. 角色跨站引用、越权授权、自我提权、修改已绑定角色提权、宿主不可管理账号均拒绝。
8. 已有成员升级前后有效权限不扩大，重复升级不会重复角色/菜单，未迁移时缺省拒绝。
9. 递归 Manifest 校验、父子登记、更新移除子菜单、只保留部分子权限、没有子权限时隐藏目录。
10. 已有 CMS 回归、独立 MySQL 迁移与事务/锁、前端权限交互、类型/构建、实际浏览器菜单与站点切换。

## 实现者决定

采用系统上限与站点角色交集；菜单在跨站有效权限并集上发现、按钮按当前站点过滤；不添加数据范围/语言/字段级策略；先保留现有功能对应的按钮，不制造未实现能力。接口名、文件分解、预置角色精确 code 列表由实施计划按上述语义列出并测试。
