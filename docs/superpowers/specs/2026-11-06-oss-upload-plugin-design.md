# OSS 全局上传插件设计

日期：2026-11-06。状态：按用户制作插件的要求实施；私有附件范围等待可选澄清，默认统一公开附件。

## 目的与边界

将对象存储作为可安装、可启停的 `oss` 插件提供，首版完整支持阿里云 OSS、腾讯云 COS、七牛云 Kodo。配置好当前云存储且插件启用后，后台附件、CMS、富文本、头像和其它经过统一 UploadService 的公开附件上传自动使用该云存储，调用方保持现有上传接口。

已向用户询问是否包含 AI 会话私有附件。默认先接管统一公开附件；AI 私有附件目前单独使用受限目录、鉴权读取和完整性检查，在用户明确选择私有云存储之前保留该语义，不能直接生成公开 URL。此项属于待确认边界。

本轮不自动迁移历史文件，不同步多云，不做浏览器直传；沿用现有服务端链路完成权限与文件校验，再调用云 SDK；写入成功后落库，落库失败尝试删除刚写入的对象。测试与开发不使用真实云凭据，也不在生产库安装迁移。

## 当前代码依据

- `admin/app/common/storage/StorageDriverInterface.php` 已定义存储驱动的 store/delete 接口。
- `StorageDriverRegistry` 目前只注册 local，UploadService 和 AdminUpload 均按 upload_driver 解析驱动；注册表可扩展，但尚无启用插件贡献驱动的通路。
- `SystemAttachment::delete` 当前会在驱动缺失时回退 local，并忽略云删除返回值后直接删除记录；接云存储前必须修正，防止删错位置或丢失追踪记录。
- 通用插件配置会写入插件 `config.php`；密码字段只在响应和数据库快照中脱敏，物理文件仍为明文。因此 OSS 凭据由插件专用服务加密落库，不复用该物理文件保存密钥。
- 当前插件支持可信激活快照、私有 serverHooks、自带 Composer vendor 和标准后台插件模块发布。沿用这些能力，不新增另一套插件加载机制。
- AI 私有附件走 AiAttachmentStorage，具有公开上传接口没有的私有目录、读校验和清理协议。

## 方案比较与选择

采用一个 OSS 插件管理三家厂商及多个存储配置，选择一个当前配置全局接管。业务上传入口继续调用宿主统一上传服务，通过通用存储钩子选择插件驱动。

分别做三个插件会重复配置、生命周期与接管逻辑，并产生多插件争抢；逐一修改 CMS/编辑器的上传地址会遗漏入口和新增插件。因此采用一个插件与一个统一接管点。实现细节由本会话据现有代码确定，不视为用户已单独批准的技术选择。

## 目录与依赖

所有路径相对项目根目录：

```text
admin/plugins/oss/
  plugin.json
  Plugin.php
  config.php                   # 不保存真实凭据
  composer.json
  composer.lock
  vendor/                      # 构建插件包时携带，安装端不运行 Composer
  hooks/storage.php
  database/migrations/001_oss.sql
  app/admin/plugins/oss/
    controller/Storage.php
    service/...                # 配置、加密、驱动、SDK 适配
  web/src/admin/plugins/oss/
    api.ts
    types.ts
    pages/Index.vue
  storage/.gitkeep
  README.md
```

安装后发布到 `admin/app/admin/plugins/oss/` 和 `web/src/admin/plugins/oss/`。后台接口使用 `/admin/plugin/oss/...`，页面为 `/#/admin/plugin/oss/storage`。不恢复 business 层，不把宿主业务接口改成云厂商地址。

依赖阿里云、腾讯云、七牛云官方 PHP SDK，插件独立锁定依赖并打入 vendor，继续走当前宿主优先与 Composer 冲突检测。正式实现时核对 SDK 官方接口与版本及 PHP 8.5 兼容性；不得让插件安装端自动执行 Composer。

## 全局接管

在宿主存储注册表增加通用的“新上传选择”和“按历史标识严格取驱动”能力，通过两个 server filter 扩展点调用已启用插件。宿主只认识 StorageDriverInterface 和通用钩子，不硬编码 oss 插件或三家 SDK。

- 新上传选择由插件当前存储配置决定，普通上传与分片合并均在最终持久化时选择。
- AdminUpload 的去重预检与 UploadService 使用同一解析规则。上传结果、附件记录、去重与写入失败补偿均使用实际驱动标识。
- 插件未启用时不加载其驱动贡献；恢复宿主原来的存储选择。
- 已启用但尚无配置时，插件设置页明确显示“未配置，尚未接管”；配置好当前存储后即自动接管。无需先填假凭据才能进入插件页面。
- 一旦配置了当前存储，凭据错误、网络超时、缺少 SDK、配置信息损坏都明确失败，不静默写到 local。
- 激活快照已经初始化但损坏时，遵循现有 fail-closed 语义；未初始化且没有插件的干净部署仍可本地上传。
- 附件管理的存储设置显示“由 OSS 插件接管”及当前配置，避免用户改回 local 但实际仍上传到云端。

## 配置与历史文件归属

插件建立 `oss_profile` 与 `oss_setting` 两张表，迁移使用标准插件生命周期。

每个存储配置获得不可变随机标识，对应不超过现有 attach.driver 30 字符限制的驱动名，例如 `oss_` 加 16 位随机十六进制值。记录厂商、桶、地域/endpoint、访问域名、目录前缀和加密凭据。

- 三家配置可以同时保存，但同一时刻只有一个当前配置接收新上传。
- 桶、厂商和定位 endpoint 变更时创建新配置，避免同一驱动名指向不同位置。原配置仍为历史附件提供删除定位；同一目标允许更新凭据。
- 使用宿主现有 Defuse 加密依赖和加密主密钥，密文绑定 oss 用途与配置 ID。无有效主密钥时拒绝保存凭据，提示补配置，不生成弱替代密钥。
- 配置读取只返回脱敏信息和“已设置”状态；空密钥表示保留原值，不将掩码作为新密钥写入。敏感字段不进入日志和插件 config.php。
- 上传目录与对象 key 由服务端校验并生成随机文件名；使用配置的访问域名生成公开 URL。

## 删除、停用、卸载、升级

- 删除附件严格按记录中的驱动名及 storage_key 操作，不能使用当前默认驱动代替。
- 驱动不可用、插件停用或云删除失败时，保留附件记录并返回明确错误；对象已经不存在时按幂等成功处理。
- 保留现有同对象多记录引用检查，避免仍有引用时删除远程对象。
- 插件停用只影响新上传接管和插件运行能力；旧公开 URL 不被重写。
- 卸载保留配置表和附件归属数据，不批量删除任何云对象；首版 purge 不支持远程文件清空。重新安装后可继续使用保留配置。
- 升级通过版本迁移更新插件表，保留旧配置标识和附件归属，不覆盖已保存的凭据。

## 管理界面

插件页展示：当前接管状态、厂商、桶/地域、访问域名、目录、各配置的启用状态；提供添加配置、修改凭据、设为当前存储、测试连接。

阿里云填写 AccessKeyId/Secret、Bucket、Endpoint；腾讯云填写 SecretId/Key、Bucket、Region；七牛填写 AccessKey/SecretKey、Bucket、上传区域和访问域名。表单仅显示当前厂商需要的字段。

连接测试走真实驱动上传并删除随机测试对象，界面事先说明行为与结果；由用户在配好真实凭据后操作。本会话只使用可控 transport/SDK doubles 验证协议，不擅自访问真实桶。测试连接不要求公开整个桶的读取权限，也不以列举所有对象作为前提。

配置与测试分别声明插件权限，并经过既有后台登录、CSRF、插件启用及权限检查。普通上传调用者继续沿用已有业务上传权限，无须额外获得云配置权限。

## 验证要求

- 无插件/停用/启用/配置切换的真实上传链，覆盖常规上传与分片最终合并。
- 三家 SDK 适配的 upload/delete 参数、对象 key、URL、幂等删除和失败补偿。
- 当前存储切换后，历史附件仍按原配置定位；目标配置不可被重写成另一个桶。
- 加密落库、响应脱敏、空密钥保留、无主密钥、权限与 CSRF 拒绝。
- 云上传失败不生成本地文件和成功记录；云删除失败保留记录；缺驱动不回退删除 local。
- 插件打包、安装、启用、停用、升级、卸载/重装、Composer 依赖加载，及源包/发布副本一致性。
- 管理页操作测试、类型检查、生产构建与现有上传/CMS/插件回归。真实三云联调依赖用户后续配置的测试桶，交付时明确区分自动化验证与真实云验证。

## 实现前审查补充

- 每次最终持久化只选择一次不可变驱动/配置实例，贯穿去重、SDK 写入、落库和失败补偿。常驻 worker 不缓存当前选择；新上传读取新状态。AdminUpload 直接使用实际上传返回的 reused 信息，不再另做驱动预检。
- 跨云服务与数据库不能保证严格原子。云端超时或清理失败保留脱敏日志中的配置 ID 与对象 key 供清理，补偿异常不能覆盖原始错误。
- 当前选择保存在插件表，不覆盖宿主 upload_driver。配置不提供物理删除入口，非当前配置仍可定位历史对象。Plugin::enabled 不要求凭据、不做云端请求；无 SDK 时可进入配置页，但禁止配置为当前/上传。
- 批量附件删除先检查所有历史驱动和 key，再逐组执行。云端发生部分失败时仅删除成功组的记录，明确返回已删除/失败 ID 并刷新列表；非 local 缺 key 拒绝删除。
- SDK 异常跨钩子边界前统一转换成脱敏消息；同时在当前宿主优先 autoload 模式下验证三家 SDK 的实际加载。
