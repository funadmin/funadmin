# CMS 自定义表单设计

## 目标与原因

CMS 站点需要让访客（客户）在前台填写并提交信息，例如“联系我们”“产品询价”“活动报名”“简历投递”。提交后，站点里有权限的成员在后台跟进处理，直到完成。

现有的“会员投稿”不适用：它要求会员登录，投稿类型固定（内容、问答），审核通过后会转成站点内容。自定义表单面向未登录的访客，字段由站点自己配置，提交结果是一条待跟进的信息，而不是内容。

## 范围

### 目标

- 每个站点在 CMS 后台配置任意多个表单：表单名称、调用代码（code）、字段列表、提交成功提示、提交按钮文字、启用或停用。
- 字段类型覆盖访客填写场景下有意义的全部类型（见“字段类型”），包括文件和图片上传。
- 表单通过 CMS 标签嵌入前台：主题中 `{{ $cms->tag('form', ['name' => 'contact']) }}`，后台数据库模板标签中 `{cms:form name="contact" /}`。HTML 由服务端渲染，样式跟随主题。
- 访客无需登录即可提交。已登录会员提交时，记录其会员 ID。
- 后台处理：
  - 提交列表：按表单、状态、提交时间、关键词筛选。
  - 提交详情：字段值、附件下载、处理时间线。
  - 跟进：写备注、改状态。状态为 新提交 → 跟进中 → 已完成，另有“无效”。
  - 导出：按当前筛选导出 CSV。
- 后台提醒：CMS 表单页面上显示“新提交 N 条”（状态为“新提交”的数量），按站点统计。
- 权限：接入现有站点权限体系，站点里拥有相应权限的成员都能处理该站点的全部提交，不做指派。
- 多语言：表单的显示文字（名称、字段标签、占位提示、帮助说明、选项文字、成功提示、按钮文字）支持按站点语言设置，未设置时回退到站点默认语言。

### 非目标（这次不做，结构上不阻碍以后加）

- 邮件、短信或站内消息通知。
- 把提交指派给某个人、“我的待办”。
- 多步骤表单、字段之间的条件显示逻辑、计算字段。
- 富文本、级联选择、树形选择、关联数据、地图定位等复杂控件。
- 表单统计报表、转化分析。
- 公开展示提交结果（例如留言墙）。

### 反目标（即使功能能用，出现这些也算失败）

- 表单定义、字段文字或任何后台可编辑的内容被编译成 Blade 或 PHP 执行。后台编辑表单的权限不等于在服务器上执行代码的权限。这与 `2026-11-09-cms-blade-design.md` 的原则一致。
- 访客上传的文件能通过 URL 被公开访问，或者被当作公开网盘滥用。
- 一个站点能看到或处理另一个站点的表单或提交。
- 提交接口可被轻易刷爆：无限写库、无限写磁盘。
- 改了表单字段之后，历史提交显示错乱，或者字段标签对不上。

## 约束

- 所有代码都在 CMS 插件内：后端在 `plugins/cms/app/cms/` 和 `plugins/cms/app/admin/plugins/cms/`，安装副本在 `admin/app/...`；后台前端在 `plugins/cms/web/src/admin/plugins/cms/`，安装副本在 `web/src/admin/plugins/cms/`。不依赖宿主的表单设计器模块（`app/admin/form`）。
- 数据库结构沿用 CMS 现有方式：用独立的 Schema 类（类似 `ContributionSchema`）定义，MySQL 迁移由 Schema 类导出，追加为 CMS 的下一个迁移文件（当前已有 `001_cms.sql`、`002_template_tag_remark.sql`）；测试用 SQLite 通过 `install()` 建表。
- 后台接口遵循现有约定：每个后台方法就是一个权限码（`cms:<资源>:<方法>`），站点操作作为 `PermissionCatalog` 里的能力权限，并通过 `CEILINGS` 映射到接口权限码，经站点角色授权。
- 前台主题正在迁移到 Blade（另一项进行中的工作，见 `2026-11-09-cms-blade-design.md`）。表单只通过 `TagRegistry` 注册标签，不直接依赖某个主题的具体文件。
- 前台站点按访问域名识别（`SiteService::byHost`），公开接口沿用这一方式确定站点，不接受客户端传入的站点 ID。
- 字段校验尽量复用 `ModelService` 现有的字段定义和校验思路（类型白名单、必填、长度、数值范围、选项），新增的类型按同样的风格实现。

## 方案选择

考虑过三种做法：

1. **在 CMS 内自建表单模块（选定）。** 后台在 CMS 里配置字段，前台由 CMS 标签在服务端渲染。和主题、站点权限、多语言自然衔接，前台不依赖大型 JS，安全边界都在插件内部。代价是字段控件要逐个实现，复杂控件不在首批范围。
2. **复用宿主表单设计器，前台嵌入 Vue 组件。** 控件最全，但前台要加载 Vue 和 Element Plus，外观与主题不一致；宿主控件里很多是后台专用的（部门、用户、关联数据、JSON）；CMS 插件会依赖宿主表单模块。
3. **宿主设计器配置，CMS 服务端渲染其中一部分控件。** 需要改造宿主设计器、维护两套格式的转换，两个模块会长期互相牵制。

用户选择了方案 1。

## 已确定的设计

### 字段类型

| 类型 | 说明 | 校验 |
|---|---|---|
| `text` 单行文本 | | 必填、最小/最大长度（上限 2000） |
| `textarea` 多行文本 | | 必填、最小/最大长度（上限 20000） |
| `email` 邮箱 | `<input type=email>` | 必填、邮箱格式（服务端校验） |
| `phone` 电话 | 不限定国家格式 | 必填、只允许数字、空格、`+ - ( )`，长度 5–32 |
| `number` 数字 | | 必填、最小/最大值、是否只允许整数 |
| `radio` 单选 | 选项列表 | 必填、值必须是已定义的选项 |
| `checkbox` 多选 | 选项列表 | 必填（至少选一个）、最少/最多选几项、值必须是已定义的选项 |
| `select` 下拉 | 选项列表，可配置为多选 | 同单选或多选 |
| `date` 日期 | `<input type=date>` | 必填、日期格式、可选最早/最晚日期 |
| `datetime` 日期时间 | `<input type=datetime-local>` | 必填、格式 |
| `time` 时间 | `<input type=time>` | 必填、格式 |
| `consent` 同意条款 | 单个勾选框，文字可含链接（受限 HTML，见下） | 必填时必须勾选 |
| `file` 文件 | 单个或多个 | 见“文件上传” |
| `image` 图片 | 单张或多张，只接受图片格式 | 见“文件上传” |
| `hidden` 隐藏字段 | 固定值，或取页面 URL 上同名查询参数（例如来源渠道） | 长度上限 500 |
| `paragraph` 说明文字 | 只用于展示，不产生数据 | — |
| `divider` 分割线 | 只用于展示，不产生数据 | — |

- 字段还有这些通用属性：字段标识（name，在表单内唯一，小写字母数字下划线）、标签、占位提示、帮助说明、是否必填、默认值、宽度（整行或半行，供主题排版用）。
- `consent` 的文字和 `paragraph` 的内容允许少量 HTML（链接、加粗、换行），必须经过 CMS 现有的 `HtmlSanitizer` 清洗后存储，渲染时不再二次解释。其他文字一律按纯文本转义输出。

### 文件上传

- 文件随表单在同一个 `multipart/form-data` 请求中提交，不提供独立的匿名上传接口。只有整份提交校验通过，文件才会落盘，这样访客无法把上传接口当网盘用。
- 每个文件字段可配置：允许的类型（从预设类别中选，如文档、图片、压缩包，或者具体扩展名）、单个文件大小上限、最多文件数。
- 系统层面的硬上限，后台配置不能超过：单个文件 20MB、单次提交所有文件合计 50MB、单个字段最多 10 个文件。
- 类型校验同时检查扩展名白名单和实际内容（MIME 嗅探）。可执行或可被浏览器执行的类型（php、html、svg、js 等）一律拒绝。
- 文件存放在非公开目录（插件私有数据目录，例如 `runtime/plugins-data/cms/forms/`，具体路径交给实现者），文件名用随机标识，原文件名只存在数据库里。
- 只能通过后台接口下载，需要“查看提交”权限，并校验文件属于该站点；响应带 `Content-Disposition: attachment` 和 `X-Content-Type-Options: nosniff`。图片可以在后台通过同一受控接口预览。
- 删除提交时，一并删除它的文件。

### 数据

实现者可以调整表结构细节，但需要具备这些信息：

- **表单**：所属站点、调用代码（站点内唯一）、名称、状态（启用/停用）、字段定义（有序列表）、各语言的显示文字、设置（成功提示、按钮文字、是否启用验证码、单 IP 提交频率），以及创建/更新时间、乐观锁版本号。
- **提交**：所属站点、所属表单、提交时的语言、提交时的字段定义快照（保证表单改版后历史提交仍能正确显示）、字段值、状态、来源页面 URL、提交者 IP、User-Agent（截断）、会员 ID（可空）、提交时间、最后处理时间、乐观锁版本号。
  - 关键词筛选覆盖提交里的文本类字段值，实现方式交给实现者，例如冗余一个搜索文本列。
- **提交附件**：所属提交、字段标识、原文件名、MIME、大小、SHA-256、私有存储路径。
- **处理时间线**：所属提交、类型（创建、备注、状态变更）、操作的管理员、备注内容、状态的前后值、时间。时间线只增不改；备注发布后不可编辑或删除，以保证处理记录可信。
- 表单有提交时不允许删除，只能停用。没有提交的表单可以删除。

### 前台渲染与提交

- 标签 `form` 接收参数 `name`（表单调用代码）。表单不存在或已停用时输出空字符串，不报错，避免拖垮整个页面。
- 渲染时先找当前主题的片段 `partials/form`，没有就用 CMS 内置的默认表单模板。内置模板只用可信的文件模板，表单定义作为数据传入，不会被编译。四套内置主题各提供一个与主题风格一致的 `partials/form`。
- 输出标准的 HTML 表单，提交到公开接口（例如 `POST /cms/forms/{code}`）。站点由请求域名确定，`code` 只在该站点内查找。
- **交互**：
  - 表单附带少量内联 JS（不依赖框架），以 `fetch` 提交。成功后在原位置显示成功提示，失败时把错误显示在对应字段旁边。
  - 浏览器禁用 JS 时，表单仍能直接提交。服务端返回一个简单的结果页：显示成功提示，或者列出错误并提供返回链接。
- 访客看到的错误和提示文字跟随当前站点语言。
- 已登录会员提交时记录会员 ID，但不要求登录。会员只通过现有的 Bearer 令牌识别：fetch 提交时如果带了有效令牌就记录会员 ID，否则留空。不新增 Cookie 形式的会员会话。

### 防刷

每个表单都启用：

- **蜜罐字段**：隐藏的输入框，被填写就静默丢弃，返回成功。
- **最短填写时间**：表单渲染时附带一个签名时间戳，提交时间离渲染不到 3 秒就拒绝；签名同时绑定站点和表单，防止伪造或挪用。签名令牌也承担 CSRF 防护的作用，公开页面可能被缓存，不依赖会话。
- **令牌有效期**：签名令牌 2 小时内有效。提供一个公开接口获取新令牌，内联 JS 发现令牌已过期时先取新令牌再提交。无 JS 提交遇到过期令牌时，结果页提示“页面已过期，请刷新后重试”。
- **频率限制**：按 IP + 表单限流，默认 10 分钟 5 次，可在表单设置里调整，并有系统上限。复用 `webman/limiter`。访客 IP 只在直连地址为内网/回环（受信任的反向代理）时取 `X-Forwarded-For` 的最后一段（没有 `X-Forwarded-For` 时才取 `X-Real-IP`），否则用直连地址；IPv6 按 /64 归并计数。

可选：表单设置里勾选“启用验证码”时，使用项目已有的 `webman/captcha` 生成图片。验证码做成无状态：答案存入缓存（`webman/cache`），用签名的验证码 ID 关联，5 分钟有效，校验一次即作废，不依赖会话。页面渲染时不签发验证码，由 `cms-form.js` 加载后请求受限流的验证码接口；无 JS 访客看到提示。

### 后台

CMS 后台新增“表单”页面，分两个标签：

- **提交**（默认）：
  - 列表显示表单、摘要（前两个文本字段）、状态、提交时间。可按表单、状态、时间范围、关键词筛选，默认只看“新提交”和“跟进中”。
  - 点开是详情抽屉，内容依次为：字段值（按提交时的字段快照排列）、附件（下载或预览）、处理时间线、写备注、改状态。
  - 支持批量标记为无效，按当前筛选导出 CSV。
  - 标签上显示“新提交 N”。
- **表单管理**：
  - 表单列表：名称、调用代码、状态、提交数。
  - 新建或编辑表单：基本信息、字段编辑器（添加、排序、按类型配置属性）、各语言文字、设置。
  - 复制嵌入代码：同时给出 Blade 主题写法和模板标签写法。

后台提醒：在 CMS 后台的表单入口处显示当前站点的“新提交”数量。显示位置（菜单角标或页面内）交给实现者，取决于后台菜单是否支持角标；最低要求是表单页面的“提交”标签上显示数量。

### 权限

在 `PermissionCatalog::groups()` 新增一组 `form`（表单）：

| 操作 | 含义 |
|---|---|
| `cms:form:list` | 查看表单 |
| `cms:form:manage` | 新建、编辑、停用、删除表单 |
| `cms:form:submissions` | 查看提交与附件 |
| `cms:form:handle` | 写备注、改状态、批量标记无效 |
| `cms:form:export` | 导出提交 |
| `cms:form:delete` | 删除提交（连同附件） |

- 每个操作在 `CEILINGS` 中映射到对应后台接口方法的权限码，规则和现有各组一致。
- 站点角色预设：“站点管理员”拥有全部；“编辑”和“发布者”获得 `list`、`submissions`、`handle`；“只读”只获得 `list`、`submissions`。（进行中的 CMS 改动已移除兼容旧成员预设 `legacy`，这里以移除后的四个预设为准。）
- `cms:form:export` 和 `cms:form:delete` 涉及批量拿走或销毁个人信息，只放在站点管理员一级。
- **已有站点的升级（用户决定）**：预设角色只在建站时写入、之后不会自动补。升级时只给已有站点中 code 为 `administrator` 的站点管理员角色补上全部表单权限，补齐操作要幂等、可重复执行。编辑、发布者、只读这些已有角色不自动补，由站点管理员按需在后台分配。新建站点照常按上面的预设写入。升级测试要覆盖：已有站点的站点管理员获得权限、其他已有角色不变、重复执行不重复写入。

## 我的决定（用户没有明确要求，由我拟定）

- 状态集合固定为四个（新提交、跟进中、已完成、无效），这次不做自定义状态。
- 时间线备注发布后不可修改或删除。
- 有提交的表单只能停用、不能删除。
- 提交时保存字段定义快照。
- 上传的硬上限：单文件 20MB，单次合计 50MB，单字段 10 个。
- 防刷默认值：最短填写 3 秒，按 IP 和表单限流 10 分钟 5 次。
- 导出和删除只给站点管理员。
- 会员只通过已有 Bearer 令牌识别，不新增 Cookie 会话。
- 签名令牌 2 小时有效，过期时由 JS 刷新；验证码无状态，答案存缓存，5 分钟有效，一次性。
- 表单的多语言文字未设置时，回退到站点默认语言。

## 交给实现者决定

- 表与字段的具体命名和类型、JSON 结构、索引设计。
- 公开接口的具体路径和响应格式（需要同时支持 fetch 和无 JS 两种提交方式）。
- 私有文件目录的具体位置，以及是否复用某个现有的存储抽象（前提是不可公开访问）。
- 内联 JS 和四套主题 `partials/form` 的具体标记与样式。
- 后台字段编辑器的交互细节。
- CSV 的列顺序和编码（需能被 Excel 正确打开中文，例如带 BOM 的 UTF-8）。
- 菜单角标能否实现；不能实现时，只在页面内显示数量。

## 验证要求

- 后端：表单配置的增删改与校验；各字段类型的服务端校验；文件上传的类型、大小、数量限制和私有存储；防刷三项（蜜罐、最短时间、频率）；跨站点隔离（他站的表单代码、提交、附件全部不可见）；权限上限与站点角色；状态流转与时间线；导出内容；字段快照在表单改版后仍正确显示。
- MySQL：新迁移文件内容必须等于 Schema 类导出的 SQL，测试用法与现有 CMS Schema 测试一致。
- 前台：标签在 Blade 主题和数据库模板标签中都能渲染；表单停用或不存在时输出空；后台可编辑的文字不会作为代码执行。
- 后台前端：组件测试覆盖字段编辑、提交列表筛选、详情处理流程。
