# 项目完整度补齐设计（仪表盘、AI、问答、OSS、接口文档）

## 目标

补齐完整度评估中标记为"部分完成"的模块。用户选定的范围如下：

| 模块 | 用户选择 |
|---|---|
| 仪表盘 | 系统概览：真实统计卡片、操作日志近 7 天趋势、最近日志、按权限显示的快捷入口 |
| AI | 实现 Fallback（备用模型）和 Reasoning（思考强度） |
| 问答插件 | 删除和回收站、问题详情与回答管理、前台 SEO 页面、会员附件 |
| OSS 插件 | 配置管理和删除、S3 兼容驱动、连接测试 |
| 接口文档 | 插件控制器和生成的业务控制器补齐 OpenAPI 注释 |

## 通用约束

- 遵守现有规则：
  - 软删除：只在回收站手动彻底删除；恢复冲突返回 409；数据表有唯一键时才加 `deleted_token`。
  - 权限码按方法推导，插件的站点操作权限要登记进 CEILINGS。
  - 后台文字中英文都要有。
  - 插件只改源码，并同步到安装副本。
  - 插件版本号随迁移一起升级。
- 共享工作区：只用 `git commit --only` 提交；不推送；不动开发库。
- 插件测试按项目约定不入库（gitignored）。需要入库的测试放到 `admin/tests` 根目录，或者 `admin/tests/Console`。

## 1. 仪表盘（系统概览）

- **后端**：新增 `GET /admin/dashboard/overview`，只读。每一块数据都先检查当前管理员是否有对应模块的查看权限，没有权限的块不返回。数据块：
  - 管理员数：未删除的管理员。
  - 会员数：总数，以及今日新增。
  - 附件：数量和占用空间合计。
  - 操作日志：今日条数、近 7 天每日条数（趋势），以及最近 10 条（只取摘要字段，不含请求体）。
  - 已安装插件：数量，以及其中已启用的数量。
- 统计查询走模型作用域，自动排除已软删除的数据，并受数据权限约束。可以缓存 60 秒，缓存键要包含管理员 id。
- **前端**：`web/src/admin/views/dashboard/index.vue` 改为调用这个接口，去掉写死的示例数据，保留现有的插件钩子插槽。
  - 卡片、图表、最近日志、快捷入口都按权限显示。快捷入口按权限过滤菜单。
  - 有加载态，接口失败时提示错误，不能显示空白页。
  - 中英文齐全。

## 2. AI：Fallback 与 Reasoning

- **Fallback**：
  - 档案里有序配置 1 到 3 个备用模型。主模型出现以下情况时，按顺序尝试备用模型：
    - 网络错误；
    - 5xx；
    - 429；
    - 超时；
    - 上游明确表示模型不可用。
  - 4xx 业务错误（如 400 参数错误、401/403 鉴权失败）不切换。
  - 每次切换都记录在任务事件和消息元数据里：用了哪个模型、为什么切换。
  - 流式输出已经开始后不再切换，直接报错，避免重复输出。
- **Reasoning**：档位按协议传给上游：
  - `openai-chat`：传 `reasoning_effort`。
  - Responses：传 `reasoning.effort`。
  - Messages：传 `thinking.budget_tokens`，按档位映射，映射表写在代码常量里，并写进文档。
  - 只有管理员在模型能力里声明支持的档位才放行；其他档位继续拒绝。
- 前端解除"保存时固定关闭 Fallback / 清空 Reasoning"的限制，更新说明文案。
- 全部用模拟上游测试，不连真实服务。

## 3. 问答插件

- **删除与回收站**：问题可以删除（软删除）；回收站可以列表、恢复、彻底删除，各有单独的权限，彻底删除需要二次确认。
  - 问题和 CMS 投稿记录的关系：删除问题时，只软删除问答侧的记录。CMS 投稿记录是否跟着删，以 CMS 现有规则为准，不擅自删除 CMS 数据。恢复问题时，如果对应的 CMS 投稿记录已被删除，返回 409。
- **详情与回答管理**：后台可以查看问题详情（标题、内容、提问会员、状态、附件、回答列表）；可以编辑状态和置顶；可以隐藏或删除回答（软删除，走同一套回收站）。
- **前台 SEO 页面**：服务端渲染问答列表页和详情页，页面包含 title、description、canonical 和结构化数据（QAPage）。只显示审核通过、未删除的内容；路由和 CMS 一样，按站点域名识别站点。
- **会员附件**：提问和回答时可以上传图片或文件。复用 CMS 会员附件的能力：类型、大小、数量限制，私有存储，以及下载鉴权。附件和问题一起软删除，彻底删除时才删除文件。
- 需要新的表或字段时，用问答的新迁移 `003`，插件版本升到 1.2.0。

## 4. OSS 插件

- **配置管理与删除**：
  - 后台可以新增、编辑、删除配置（软删除），并切换当前使用的配置。
  - 不能删除当前正在使用的配置（返回 409）。
  - 回收站支持恢复和彻底删除。
  - 已有附件引用 `oss_<id>` 驱动时，彻底删除返回 409，或要求先迁移附件；这里选择返回 409。
  - 第 2 步评审留下的问题一起处理：已删除配置对应的附件仍然要能读取和删除，`resolve` 路径用 `withTrashed`。
- **S3 兼容驱动**：
  - 新增 `s3` 供应商，适用于 AWS S3、MinIO、Cloudflare R2 等。
  - 配置项：endpoint、region、bucket、访问密钥、是否使用 path-style、公开访问地址前缀。
  - 依赖用 `aws/aws-sdk-php`，可选安装（`class_exists` 检测），和现有三家的做法一致。
  - 密钥同样加密保存。
- **连接测试**：配置页面加一个"测试"按钮。点击后上传一个随机小文件、读取校验、再删除，返回每一步的结果。用当前表单里的值测试，不需要先保存。超时控制在 15 秒以内。
- 需要迁移时用 OSS `003`，插件版本升到 1.2.0。

## 5. 接口文档

- **范围**：给 CMS、文档、问答、OSS 的后台控制器和公开控制器，以及代码生成器产出的业务控制器模板，都补上 OpenAPI 注释。
  - 格式遵循 `docs/openapi/README.md` 的约定：完整 path、唯一的 operationId、参数位置正确、响应模型。
  - 插件的标签在 `docs/openapi/ApiDocumentation.php` 中登记。
- **生成器**：`ProductionTemplateContext` 生成控制器时同时生成注释，生成结果要能通过文档扫描。
- **防回退测试**：新增一个入库测试，用 swagger-php 扫描（如果依赖已经存在，就用它的 Generator；否则做静态检查），断言：
  - 每个有路由属性的后台、插件控制器方法都有对应的 `@OA` 操作；
  - path 和路由一致；
  - operationId 全局唯一。
