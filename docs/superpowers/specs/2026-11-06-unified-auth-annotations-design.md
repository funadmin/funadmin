# 后台与会员 API 统一鉴权写法 — 设计

日期：2026-11-06
状态：已确认（方案 1：统一写法，接口仍按身份分开；后台 `#[Permission]` 为可选）

## 背景与目的

项目现有四种鉴权写法：后台 `CheckAdminApiRoleMiddleware`（按控制器/方法推导资源，查数据库 `permission` 表）、插件后台 `#[PluginPermission]` 注解、会员 API `ApiMiddleware` + `#[NoNeedLogin]`、插件会员路由 `memberApiGroup()`。规则分散在中间件硬编码、路由文件、数据库三处，看一个接口是否需要登录或权限要来回查，也容易出现"以为受保护其实没有"的接口。

目标：后台与会员 API 用同一套注解声明"是否需要登录、需要什么权限"。接口地址、登录方式、数据范围仍按身份分开，保留物理隔离带来的安全性。

## 目标

- 一组共享注解：`#[NoNeedLogin]`、`#[NoNeedPermission]`、`#[Permission('code')]`。
- 一个共享的注解解析组件，后台和会员中间件都调用它。
- 中间件内的硬编码特例改为注解。
- CRUD 生成器、插件会员路由与约定一致。

## 非目标

- 不统一登录方式：后台仍为 Cookie 会话 + CSRF，会员仍为 Bearer。
- 不统一响应格式：两边各自协议不变。
- 不改数据库权限数据、Casbin 配置、角色。
- 会员端不做权限码（`#[Permission]` 在会员端暂不支持，见下）。
- 不合并后台与会员接口地址。

## 反目标（即使"能跑"也算失败）

- 任何现有后台接口的登录或权限要求被放宽。
- 会员端因注解解析失败而放行（解析失败必须按需要登录处理）。
- 已在用的 `#[PluginPermission]` 插件失效。

## 约束

- 注解默认需要登录；忘标注只会更严格。
- 注解解析按进程缓存；无法解析目标控制器时一律按"需要登录、需要权限"处理。
- 后台 `#[Permission]` 可选：未标注时保持现有"按控制器/方法推导资源并查库"的行为，以及库内 `is_public`。
- 中间件命名遵循已完成的 `*Middleware` 后缀约定。

## 方案对比

| 方案 | 说明 | 取舍 |
|---|---|---|
| **1. 统一写法，接口分开（选定）** | 共享注解与解析组件，两端中间件按注解判断；登录方式、数据范围、接口地址分开 | 解决写法分散与漏洞隐藏问题，保留隔离；改动可控 |
| 2. 统一身份与令牌 | 管理员与会员都走 `identity_user` 与统一令牌 | 工作量大，后台前端需改为 Bearer |
| 3. 完全同一套接口 | 同一 URL 按身份分数据 | 越权与字段泄露风险最高 |

## 已决定的设计

### 注解（`app/common/annotation/`）

| 注解 | 目标 | 含义 |
|---|---|---|
| 不标注 | — | 需要登录（后台还需权限） |
| `NoNeedLogin` | 类/方法 | 不用登录；若带有效身份仍注入当前用户 |
| `NoNeedPermission` | 类/方法 | 登录即可，不校验权限码（仅后台有意义） |
| `Permission(string\|array $code)` | 类/方法 | 指定权限码；数组表示任一满足（后台可选；会员端暂不支持，标注时会员中间件按需登录处理并忽略权限） |

方法注解优先于类注解；类注解沿父类链查找。

### 后台权限码来源

- 标了 `#[Permission]`：以注解为准。
- 未标：保持现状（推导资源 → 查 `permission` 表 → `is_public` 或权限码匹配）。

### 插件权限

`#[PluginPermission]` 保留并继续生效；`#[Permission]` 在插件控制器上等价。插件市场按 action 名硬编码的映射改为在方法上标注解。

### 硬编码特例 → 注解

- `admin/adminprofile` 免权限 → `AdminProfile` 类标 `#[NoNeedPermission]`。
- 插件页面目录 `enabledModules` 免权限 → 方法标 `#[NoNeedPermission]`。
- 插件市场控制器 action 映射 → 方法标 `#[PluginPermission]`。

### 生成器与插件会员路由

- 生成的会员 CRUD 控制器、插件非后台控制器改为继承 `ApiController`。
- `memberApiGroup()` 保留中间件挂载；`ApiMiddleware` 对同一请求只执行一次鉴权，避免与控制器重复。

## 留给实现者

- 解析组件的具体缓存键与反射细节。
- 权限快照的存储格式（只要能逐方法比较登录/权限要求）。
