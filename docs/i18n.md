# 多语言维护约定

## 前端词条

`web/src/shared/locales/zh-CN.ts` 和 `en-US.ts` 是稳定导入入口。实际词条按命名空间拆在对应目录，例如：

```text
web/src/shared/locales/
  zh-CN.ts
  en-US.ts
  zh-CN/common.ts
  en-US/common.ts
  zh-CN/cms.ts
  en-US/cms.ts
  zh-CN/community.ts
  en-US/community.ts
```

新增词条必须同时提供中英文，保留相同的键与插值参数。界面通过 `t('cms.labels.save')` 等键取值；计数使用完整消息和复数分支，不拼接翻译后的碎片。会随界面语言变化的选项、状态及标题应使用计算属性或调用时求值，避免在模块导入时固定语言。

CMS、问答、会员页面、富文本控件及编辑提醒已经接入语言包。用户创建的栏目名、模型字段标签、正文、配置值以及服务端返回的数据不是静态界面词条，按其自身的数据语言展示，不做全文替换。

数据库译文通过现有语言管理接口覆盖本地词条；删除覆盖后回到本地默认值。本地包仍是离线和未登录时的兜底，不要把数据库覆盖直接写回源码。

## 后端词条

使用 Webman 的 `<根目录>/<locale>/<domain>.php` 结构：

```text
admin/app/admin/lang/zh-cn/messages.php
admin/app/admin/lang/en-us/messages.php
admin/app/common/lang/zh-cn/messages.php
admin/app/common/lang/en-us/messages.php
```

默认域是 `messages`，已有的 `trans()`、`__()` 和 `lang()` 键保持兼容。公共词条由 `common` 持有，避免在 `admin` 重复定义；兼容旧系统时保留原先生效的公共词条优先级。旧根目录语言文件及错误嵌套的 auth/member 文件已合并到规范目录，迁移前后的中文键值由测试快照校验。

CRUD 生成的 `<locale>/<entity>.php` 保持原生成路径和嵌套对象格式。`GeneratedLanguagePacks` 将其注册为默认域的点分键，按 translator 对象去重；每次请求不会重复增加资源。修改或生成 PHP 语言文件后，按现有部署流程重载 Webman worker。不要手工修改已执行的语言 SQL 迁移或历史发布包。

## 界面语言与内容语言

前端用 `X-Locale` 请求头发送界面语言。后端选择顺序为有效请求头、query `locale`、Cookie、默认值，兼容 `zh-CN`、`zh_CN` 等格式。CMS 请求中的 `locale` 参数仍用于选择站点内容语言，不能据此改写界面或数据。

前端内部使用 `zh-CN` / `en-US`，后端资源目录使用 `zh-cn` / `en-us`。已有转换与数据库覆盖逻辑负责规范化。

## 自动检查

在 `web/` 运行：

```sh
npm run check:i18n
npm test -- tests/i18n tests/cms/localization.spec.ts
```

检查包括中英文键一致、插值参数一致、对象重复键和实际源码中的静态翻译引用。`crud.*` 的生成词条由各自迁移写入数据库，检查器明确区分这类键。`npm run scan:i18n` 可辅助排查硬编码中文；它的结果需要区分界面文本、中文兜底及用户数据，不能直接批量删除。

后端专项检查：

```sh
cd admin
php vendor/bin/phpunit tests/BundledLanguageTest.php tests/LoadLangPackContractTest.php
```

这些测试只使用隔离测试环境，覆盖旧键保留、英文完整性、占位符、深层历史词条、生成词条、多 translator 和重复请求资源稳定性。
